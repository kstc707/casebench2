# How Casebench 2 works

A one-page map of the app's parts and where each lives. For the story of how it was built, see
`docs/build-log/`. Paths are from the repo root.

## The big picture

There are three flows. One prepares the tasks ahead of time. The second runs a student's tests in the
browser. The third, the coach, helps them prepare a pull request once a task is solved (section 5 below).

```
Preparing tasks (developers and CI)          Using the app (the student's browser)

content/scikit-learn/sources.json            page (Next.js, static HTML + React)
        │                                            │  student presses a run button
        ▼                                            ▼
builder  build-sklearn-tasks.ts              worker  runner-worker.mjs (background thread)
        │  writes task folders                       │  passes the student's file + test ids
        ▼                                            ▼
content/scikit-learn/<slug>/                 runner.py (Python, inside Pyodide)
        │                                            │  writes the file over scikit-learn,
        ▼                                            │  clears old modules, puts the original back
checker  check-sklearn-tasks.ts (CI)                 ▼
   "does every real fix still pass?"         pytest in Pyodide → results back to the page
```

The builder and the checker use the same `runner.py` as the browser, through `apps/web/lib/runner/runner.ts`
(the Node side). A task is always tested the same way, whether by CI or by a student.

## 1. Content: the tasks

`content/scikit-learn/`
- `sources.json`: the list of tasks (PR number, merge commit, the 1.8.0 base) in suggested order.
- `<slug>/`, one folder per task:
  - **Generated by the builder:**
    - `task.json`: the test lists (fail→pass, pass→pass, skipped).
    - `before/`: the file the student starts from (scikit-learn 1.8.0).
    - `tests/`: the PR's test file, shown read-only.
    - `tests.diff`: the PR's change to the test file.
    - `solution/` and `fix.diff`: the real fix.
  - **Written by hand:** `about.json` (title, what it teaches, summary, quotes, where to look).
  - **Made from a scikit-learn clone:** `source.md`, the upstream text every quote must match
    (`apps/web/scripts/make-sklearn-sources.py`).
- `LICENSE`: scikit-learn's license.

## 2. Builder and checker (run from the command line)

| File | What it does | Command |
|---|---|---|
| `apps/web/scripts/build-sklearn-tasks.ts` | Applies each real fix to 1.8.0, runs the whole test file before and after, writes the task folder. Refuses bad tasks (rules in `apps/web/lib/sklearn/taskRules.ts`). | `pnpm --filter @casebench2/web build-tasks --repo <scikit-learn clone>` |
| `apps/web/scripts/check-sklearn-tasks.ts` | Re-runs every task from scratch and fails if anything differs from `task.json`, `fix.diff` or `tests.diff` (rules in `apps/web/lib/sklearn/checkTask.ts`). | `pnpm --filter @casebench2/web check-tasks` |
| `apps/web/scripts/prepare-pyodide.mjs` | Downloads Pyodide 314.0.7 once, checks every file's SHA-256, copies the 23 needed files to `apps/web/public/pyodide/314.0.7/`. | `pnpm --filter @casebench2/web pyodide` |

CI (`.github/workflows/ci.yml`) has two jobs: `check` (typecheck and unit tests) and `tasks` (Pyodide
tests and the checker).

## 3. The app (what the student sees)

| Page | URL | File |
|---|---|---|
| Home | `/` | `apps/web/app/page.tsx` |
| The path (5 tasks, statuses) | `/scikit-learn` | `apps/web/app/scikit-learn/page.tsx` |
| A task | `/scikit-learn/<slug>` | `apps/web/app/scikit-learn/[slug]/page.tsx` → `apps/web/components/task/TaskWorkspace.tsx` |

Supporting files:
- `apps/web/lib/tasks.ts`: reads `content/scikit-learn/` when the site is built, so the pages are
  static.
- `apps/web/lib/progress.ts`: progress and drafts in the browser's localStorage
  (`casebench2.progress.v1`, `casebench2.draft.v1.<slug>`).
- `apps/web/lib/sklearn/runReport.ts`: decides "solved" (`judgeCheck`) and writes plain error messages
  (`explainRunError`).
- `apps/web/lib/sklearn/inlineCode.ts`: shows code names in the text as code.

## 4. Running tests in the browser

| Step | File | Role |
|---|---|---|
| Page | `apps/web/lib/runner/useTestRunner.ts` | Starts the worker when the task page opens; one run at a time; 60 s / 120 s limits, then restarts Python. Timer bookkeeping lives in `pendingRuns.ts`. |
| Worker | `apps/web/scripts/runner-worker.mjs` | A background module worker. Loads Pyodide, scikit-learn, its tests and pytest, then passes each run to Python. Served from `public/pyodide/` (not bundled by Next.js). |
| Python | `apps/web/lib/runner/runner.py` | Writes the student's file over the installed scikit-learn file, clears `sklearn` modules, runs exactly the given tests (with the offline stand-in image for #33643), puts the original back, returns JSON results. |
| Tests | pytest 9.0.2 inside Pyodide 314.0.7 | scikit-learn 1.8.0's own tests. |

Shared types and limits: `apps/web/lib/runner/types.ts`.

## 5. The coach: "Prepare your pull request"

It appears on the task page once the task is solved. Everything runs in the student's browser.

```
content (scikit-learn's rules + coach.json per task)
        │
        ▼
checks (no AI)                retrieval (BM25, no AI)
 code, PR form, changelog      picks rule passages R1…R8
        │                              │
        └──────────────┬───────────────┘
                       ▼
review request (optional, student's own API key)
 diff + PR text + changelog + answers + checks + rules → api.anthropic.com
                       ▼
panel: verdict, comments citing rules, covered/missed key points,
tokens, cost estimate, time, thumbs up/down, "Download coach log"
```

| Part | File |
|---|---|
| scikit-learn's own rules (copied unchanged; the commit is in `SOURCE.md`) | `content/scikit-learn/contributing/` |
| Questions and key points (rubric) per task | `content/scikit-learn/<slug>/coach.json` |
| Automatic checks (scope, style, PR form, changelog) | `apps/web/lib/coach/checks.ts` |
| Split the rules into passages (build time) | `apps/web/lib/coach/passages.ts` (reuses `packages/team-memory`) |
| BM25 search over the passages (browser) | `apps/web/lib/coach/retrieval.ts` |
| Request, JSON schema, API call, error handling | `apps/web/lib/coach/review.ts` |
| Saved state, review log and key (localStorage) | `apps/web/lib/coach/storage.ts` |
| The panel (4 stages) | `apps/web/components/coach/CoachPanel.tsx` |
| End-to-end check (mocked API, run by hand) | `apps/web/e2e/coach.mjs` |

The AI review has not yet run against the real API (build log 03).

## Where to look when…
- **A task's text is wrong:** `content/scikit-learn/<slug>/about.json`, checked by
  `apps/web/lib/sklearn/about.test.ts`.
- **A task's tests or fix are wrong:** rebuild with the builder; the checker tells you what differs.
- **A run shows a confusing message:** `apps/web/lib/sklearn/runReport.ts` (wording) or
  `apps/web/lib/runner/runner.py` (what Python reports).
- **Loading is slow or fails:** `apps/web/scripts/runner-worker.mjs` and `prepare-pyodide.mjs`.
- **Testing the whole flow in a real browser:** `apps/web/e2e/sklearn-track.mjs` and `apps/web/e2e/coach.mjs`
  (run by hand).
- **The coach says something wrong:** the prompt and schema are in `apps/web/lib/coach/review.ts`, the
  rubric in `coach.json`, and the rules it saw are in the coach log (`rules`).
- **The team's notes and decisions:** `.claude/team/` (search them with `pnpm team:ask "…"`).
